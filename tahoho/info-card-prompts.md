# 課程資訊卡 Prompt 集（tahoho）

每個章節一副牌，貼進 Claude 觸發 `/info-card-generator` 即可。
格式對齊講義「匯入別人建立好的 Skill」段的範例：素材 → 主題 → 條列要點 → 結尾卡 → 依據。

- 每副 5–7 條要點 → 含封面與結尾卡剛好落在 5–10 張的 criteria 內
- 所有數字（50 封、30 天、20 美金…）皆出自講義，未考證的不寫
- 結尾卡一律要求「自檢清單」＋「依據」，方便同仁回到講義核對

---

## 1. 起手式：設定與使用時機

```prompt
/info-card-generator
素材：AI 教育訓練第一章「起手式」，內容是開始用 Claude 前要完成的設定、模型怎麼選、六種功能什麼時候用。做成知識卡給還沒上課、剛拿到公司帳號的同仁，照著做就能把環境準備好。
主題：「為什麼別人的 AI 比我的強？開始前先做這 6 件事」

1. 先關訓練資料：到官網下載桌面版 App，左下角頭像 → Settings → Privacy，關閉「Location metadata」與「Help improve our AI models」，第一次登入就先做。
2. 讓 Claude 更了解你：Settings → Account，「What best describes your work」選自己的工作，「Instructions for Claude」寫協作方式（優先拆解需求、避免空泛描述、資訊不足時反問 1 至 2 個問題）。
3. 賦予能力原則上全開：Settings → Capabilities，Connector search、Switch models、Artifacts、Code execution 都開；只有「Tool access mode」維持預設 Load tools when needed，全部載入會浪費 Token。
4. 模型怎麼選：Sonnet 是日常主力；Opus 做複雜分析、長篇寫作、程式開發；Fable 留給最困難、需要推理的任務；Haiku 跑簡單問答、摘要、大量重複的小任務。越聰明的模型花越多 Token。
5. 六種功能一句話：Connector 給它眼睛跟手、Project 給它參考資訊、Skill 給它 SOP 手冊、Cowork 給它工作桌、Scheduled 給它鬧鐘、Claude Code 請它做一個工具。
6. 沒有程式背景先用 Cowork：Claude Code 能做 Cowork 的所有事，但更危險；當它詢問權限、要執行腳本時，大多數人會「接受」而不是「確認」，搞錯一次就可能出現資安危機。

結尾卡放一份「開始用 AI 前的自檢清單」，依據寫「AI 教育訓練講義・起手式」。
```

## 2. Connector：信箱與行事曆

```prompt
/info-card-generator
素材：AI 教育訓練第二章「串接日常工具」，示範用 Connector 接 Gmail、Google Calendar、Microsoft 365，讓 AI 分類信件、彙整討論串、把信件轉成行事曆事件。做成知識卡貼在部門群組，重點是「授權之後、動手之前要確認什麼」。
主題：「讓 AI 讀你的信箱之前，先知道這 6 件事」

1. 怎麼接：Customize → Connectors，選 Gmail、Google Calendar 或 Microsoft 365 點「+」。公司信箱是 Outlook 就接 Microsoft 365，一次打通 Outlook、Teams、OneDrive、SharePoint；出現「需要管理員授權」代表權限還沒開，找 IT。
2. 信件分三桶：🔴 重要（主管、客戶、廠商直接寄給我，要回覆或決定）、📁 封存（系統通知、公告、我只是 CC、已處理完）、🗑️ 刪除候選（電子報、促銷、過期通知）。有疑慮時優先歸封存，不歸刪除候選。
3. 先小範圍測試：先跑最近 7 天、前 50 封；只讀寄件人與主旨不讀內容；先給清單，我說「確認執行」才套標籤；不刪除、不移動任何信件。沒問題再擴大範圍、調整規則。
4. 刪除留給人：Claude 接上 Gmail 後可以讀信、建草稿、建標籤，但刪除這種高風險操作由人在標籤建好後自己判斷；刪除後 30 天會永久消失，有些系統通知依舊重要。
5. 散落的討論串交給 AI 彙整：給一個關鍵字（合作對象、信件主旨），AI 就能把跨越數個月、多封往返的細節整理成脈絡，再請它依脈絡擬回覆草稿。
6. 信件轉行程要先看草稿：請 AI 抓最後會議的日期時間地點、把議程重點寫進事件說明、把討論人員設為 attendees、和現有行程衝突先提醒，建立前先給草稿過目。Claude 是真的會建行程，也會出現在與會者的日曆上。

結尾卡放一份「授權後、按下確認前的自檢清單」，依據寫「AI 教育訓練講義・串接日常工具」。
```

## 3. Project：專屬知識庫

```prompt
/info-card-generator
素材：AI 教育訓練第三章「建立專屬知識庫」，用「廠務與系統類提案的決議追蹤」專案示範：指令怎麼寫、定版文件與會變動的文件分別怎麼放、怎麼驗證 AI 回答有出處。做成知識卡給要建立部門知識庫的同仁。
主題：「不必每次重講背景：建 Project 要記住這 7 件事」

1. 什麼時候該開 Project：你扮演的角色不同（組員、主管、甲方、乙方、顧問）、手上多個案子並行（不同廠區、不同系統、不同廠商）。Project 目前無法分享，是個人使用設計。
2. 三個組成：指令 Instructions（我是誰、專案在做什麼、固定規則）、知識庫 Files（提案單、會議記錄、決議日誌、內規）、記憶 Memory（用一段時間後更懂你）。
3. 指令要先畫地圖：告訴 AI「什麼問題去哪份文件找」。議事錄記過程、決議日誌記理由、追蹤表記進度、規範記紅線；先給這張地圖，它就不會拿議事錄猜進度、拿追蹤表猜理由。
4. 回答原則寫進指令：一律以知識庫為準並標出處；找不到就明說「目前文件沒有記錄」，不臆測；記錄互相矛盾時以日期較新的為準並提醒；已被取代的決議要補一句「原本是…後來因…改為…」。
5. 定版的直接上傳：簽核完的議事錄、公告生效的內規，發出去就不會再改，PDF 直接拖進 Files。注意掃描或拍照的 PDF 其實是圖片，要先轉成文字 AI 才讀得到。
6. 會變動的放雲端用連結：提案單追蹤表每週改狀態、決議日誌每次開會多一條，放 Google Drive 用連結加入知識庫；雲端改完 AI 下次回答就是新的，團隊共用同一份不會各拿各的舊檔。
7. 建好後用三個問題驗證：問一次決議與待辦，看出處有沒有附；故意擬一段違反內規的條文，看違規有沒有被抓出來；問一個文件裡不存在的案子，看它會不會誠實說沒有。

結尾卡放一份「定版用上傳、會改的放雲端」的判斷表與自檢清單，依據寫「AI 教育訓練講義・建立專屬知識庫」。
```

## 4. Skill：把好方法變成 SOP

```prompt
/info-card-generator
素材：AI 教育訓練第四章「把好方法變成 SOP」，用 skill-creator 建立工作日誌 Skill、迭代加入信箱與行事曆來源、驗證觸發方式、分享與匯入，以及安裝 Skill 的經驗談。做成知識卡給要幫部門建 Skill 的同仁。
主題：「把最好的一次變成每一次：建 Skill 前先記住這 7 件事」

1. Project 放知識，Skill 設計流程：Project 讓 AI「知道事實」（角色、規範、議事錄、案子進度），Skill 讓 AI「知道步驟」（簽呈、會議記錄、月報、信件要遵守的 SOP）。
2. 用白話建雛形，不要手刻：Customize → Skills → skill-creator，描述名稱、資料來源、輸出重點與規則（避免流水帳、不誇大、不編造、繁體中文）；完成後記得點「Save skill」。AI 設計的 Skill 常有過度設計、冗贅資訊，依實戰結果再修。
3. 先求有，再迭代：第一版確認輸出結構符合期待，再用 skill-creator 加新需求，例如加入信箱與行事曆來源，並補一條「Connector 沒接就依讀得到的資訊處理」；完成後點「Update」。這份講義的 Skill 迭代超過 100 次。
4. 兩種觸發方式：用意圖或關鍵字被動觸發，因為 Skill 會越來越多，記不住每個名稱；用「/skill-name」主動觸發，要在一段對話裡組合多個 Skill 時比較穩定。
5. 一般對話與 Project 的記憶是分開的：在 Chat 觸發讀得到跨對話的紀錄，但讀不到 Project 裡的內容；想整理某個專案的工作，就進到那個專案再觸發。
6. 分享與匯入：Customize → Skills 可下載要分享的 Skill；Add → Upload a skill 可匯入，接受 Markdown、.zip、.skill 三種格式。新人拿到前輩的 Skill 也能做出符合公司期待的成果。
7. 不是越多越強：同類型的 Skill 裝兩個以上，需求命中時常一起觸發，多花 Token 還容易卡住走偏；同類擇優裝一個。網路上很多 Skill 只是看起來有用，裝太多沒用到的會讓 AI 行為更難預測。

結尾卡放一份「建 Skill 自檢清單」，依據寫「AI 教育訓練講義・把好方法變成 SOP」。
```

## 5. Cowork：讓 AI 動手處理檔案

```prompt
/info-card-generator
素材：AI 教育訓練第五章「讓 AI 動手處理檔案」，四個 Cowork 案例：讀一包檔案做對應、收據照片批量寫進 Excel、12 個月 KPI 工作表畫成趨勢圖、五間公司 Excel 抄進總表。做成知識卡給要用 Cowork 處理報表與檔案的同仁，重點是「怎麼下指令、怎麼驗收」。
主題：「讓 AI 動手前，先讓它讀懂：Cowork 要記住這 7 件事」

1. Cowork 會真的動你的檔案：桌面 App 左側欄，Pro 以上方案才看得到；它能新增、修改、刪除電腦檔案，剛開始選「Ask」、限定資料夾。先想想「做到一半額度沒了會發生什麼事」。
2. 先讀檔案、做對應，不急著做事：讓它讀完整個資料夾，用「內容」判斷每個檔案在講什麼（檔名不可靠），輸出對照表；對不到的檔案、沒附檔的需求、不確定的對應都要列出來，指令結尾加「先不要做其他事」。
3. 照片轉 Excel 的三條規則：一張照片一列、最後一欄標明來源照片檔名、看不清楚或不確定的格子留空並標黃，不要自己猜數字。
4. 多層合併表頭先讓 AI 說結構：請它說明每張工作表的表頭、廠區、KPI 項目、哪些月份還沒填，確認沒對錯位再往下做。要能分辨「真的 0」跟「還沒填」，沒填的留空不補 0；產圖存成新檔，原檔不要動。
5. 格式不一致的多檔彙整，先對欄位再抄數字：先列「總表欄位 ← 各公司對應欄位」對照表給你確認，對不上就停下來問；陷阱有千分位文字、欄位順序不同、多抬頭列、明細在第二張工作表、民國年日期。公式欄不覆蓋，精簡只提案不自己刪。
6. 驗收方法是抽一格對：不同月份、不同廠區各抽一格，其中一格挑在合併表頭的邊界；圖上的線數要等於廠區數；點一下「餘額」儲存格，確認還是公式不是被貼成數字。
7. 流程跑順就存成 Skill：一句「幫我將這個工作流轉為 Skill」。判斷標準是這件事允不允許「差不多」：內容每次不同、要 AI 判斷的用 Skill；規則固定、不能有意外的做成工具。

結尾卡放一份「Cowork 指令與驗收自檢清單」，依據寫「AI 教育訓練講義・讓 AI 動手處理檔案」。
```

## 6. 排程：固定要做的事交給 Scheduled

```prompt
/info-card-generator
素材：AI 教育訓練第五章末段「把固定要做的事交給排程」，說明 Scheduled 怎麼運作、怎麼建立、任務說明要寫清楚哪五件事，以及先手動跑順再排程的提醒。做成知識卡給要設定法規追蹤、產業新聞、專案進度彙整等定期任務的同仁。
主題：「每週都要做的事，為什麼每週都要自己記得？排程前先看這 5 件事」

1. 它在雲端跑：時間到就執行，電腦睡眠或 App 關閉也照常；頻率可設每小時、每天、每週、平日或手動。資料來源是網路研究、已授權的 Connector、存在 Claude 帳號裡的檔案，無法綁定電腦裡的資料夾。所有付費方案都能用，Team 與 Enterprise 要管理員先開啟 Cowork。
2. 怎麼建：左側欄「Scheduled」→「New task」→ 選「Create with Claude」讓它反問細節，再提出任務名稱、頻率與指令 → 確認後按「Schedule」。之後可在同一頁暫停、修改、刪除或手動立即執行。
3. 任務說明要寫清楚五件事：資料來源（去哪裡找、什麼條件）、執行頻率、什麼算「新的」（只列最近 7 天）、輸出格式（表格：日期、標題、重點、來源連結）、人工覆核（不確定的標「待確認」）。
4. 不要拿舊資料湊數：沒找到新資料就回覆「本週無新增」；不確定是否跟業務相關的標註「待確認」，不要自行判斷。
5. 先手動跑順，再交給排程：排程會自動執行、自動消耗額度，先手動跑幾次確認穩定；任務會寄信、發訊息或更新其他系統的，先確認 Connector 權限範圍。排程只會重複執行流程，不會幫你把流程變正確。

結尾卡放一份「開啟排程前的自檢清單」，依據寫「AI 教育訓練講義・把固定要做的事交給排程」。
```

## 7. Vibe Coding：做出自己的小工具

```prompt
/info-card-generator
素材：AI 教育訓練第六章「可重複使用的工具」，用同仁的排課需求示範 Vibe Coding 六步驟，再做帳單分類器與離群值篩選器；強調從日常痛點出發、純前端資料不出電腦、驗收一定要親手做。做成知識卡給沒有程式背景、想自己做工具的同仁。
主題：「你不需要會寫程式，但一定要驗收：Vibe Coding 的 6 件事」

1. 從日常工作的痛點出發：別再做記帳軟體、番茄鐘，缺少挫折的練習幫助有限。日常工作你有能力分辨對錯、遇錯不會輕易放棄；陌生領域你看不出 AI 犯錯，就像做醫院排班工具時以為是對的，護理長一試就發現問題。
2. 六步驟一條路：先讀懂（讓 AI 說明資料關係、列出還缺哪些資訊，先不要寫程式）→ 定規則（寫成可以檢查對錯的句子，再問「有推薦的組合嗎」）→ 收斂到雙擊 html 就能用（建「code」資料夾、純前端、要有預覽並把衝突標紅）→ 要求撰寫測試程式 → 用反例驗收 → 給真實使用者試用。
3. AI 的自我驗證通過，不代表真的通過：成品一定要親手打開，故意製造衝突（同一帳號同一時段排給兩個人）、把某人整週設請假，看工具有沒有抓到。
4. 回報錯誤不要說「怪怪的」，要說「哪裡不對」：誰、哪個時段、哪個帳號，具體反例能讓 AI 直接找到錯，也要求它把這個情境加進測試程式。
5. 純前端＝資料不出你的電腦：沒有後端、沒有資料庫，所有運算在自己的瀏覽器跑，可以放心在公司電腦甚至離線使用。想存資料、分權限、串公司帳號就是另一個世界，雛形可以 Vibe Coding，隱私交給專業工程師。
6. 能力越強風險越大：寫程式會建立、覆蓋整個資料夾，先選「Ask」、限定資料夾；牽涉客戶或同事個資的檔案先去識別化再給 AI。看起來能動的東西最危險，AI 的錯會全部算在你頭上。修 Bug 靠方法不靠運氣：換個問法、附上證據、調高 Model 與 Effort、或開一個新對話。

結尾卡放一份「工具上線前的驗收清單」，依據寫「AI 教育訓練講義・可重複使用的工具」。
```

## 8. 總結：Work Smart, Don't Work Hard

```prompt
/info-card-generator
素材：AI 教育訓練最後一章「課程總結」與「諮詢時段」，回顧今天走過的六步、五大功能一句話定義、面對新工具焦慮的判斷方法，以及把方法套回自己工作的描述模板。做成知識卡當課後回顧，貼在公告讓沒上課的同仁也能抓到全貌。
主題：「從聊天工具升級成工作幫手：今天走過的 6 步」

1. 今天的路線：守住底線（個資與機密不貼，先去識別化）→ 接上工具（Connector 讀信箱與行事曆，動手前確認範圍）→ 固定背景（Project 放規格與會議紀錄）→ 保存做法（好流程做成 Skill 分享）→ 交付成品（Cowork 讀檔案、寫 Excel、畫圖、彙整，定期工作交給排程）→ 做出工具（規則固定的事用 Vibe Coding 做成純前端網頁，親手驗收）。
2. 五大功能一句話：Connector 透過授權在 Claude 操作多個線上工具；Project 上傳知識庫、設定指令，免每次交代背景；Skill 把好流程變 SOP，讓 AI 從通才變專才；Cowork 指定電腦資料夾讓 Claude 接手任務；Vibe Coding 從自己的需求做小工具，AI 負責做、你負責驗收。
3. 看到新名詞先問三件事：先觀察一段時間（剛推出往往不完善、沒教學）、有沒有具體成功案例（還是只有話題性）、對你有幫助嗎。Demo 都是挑過的，漂亮網頁多半是框架的功勞，看不懂不代表你不行。
4. 導入 AI 不代表全交給 AI：讓 Agent 跑很久不一定最強；好的結果不該靠消耗 Token 拼運氣，而是靠清楚的方向、可重複的工作流、以及人在關鍵節點的決策。
5. 不要有預設立場，先讓 AI 試試看：腦中冒出「不確定 AI 能不能做到」就直接試；工作上有乏味的電腦或紙本作業就是嘗試付費的契機，Pro 版 20 美金跟一個人的薪水相比非常便宜。把執行交給 AI，把判斷留給自己。
6. 讓 AI 回頭看看你：請它把最近一個月的對話抓出來復盤，你問了哪類知識、用了哪些工具、怎麼解決問題、哪些常問卻沒建成 Skill。你問 AI 的問題，藏著你最想解決的事。
7. 把方法套回自己的工作，先用一段話描述情境：我的工作是[職務]，每[週／月]要做[任務]，資料來源是[檔案或系統]，最後要交出[成品]，目前最花時間的是[哪一步]；請 AI 判斷適合 Connector、Project、Skill、Cowork、排程還是 Vibe Coding，並說明第一步。
```
