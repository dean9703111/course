# ERP 維護績效月報產生器

使用者會丟一份 Excel（通常是 ERP 派工單匯出＋人工加註後的三張工作表），要拿到跟
「2024_BL_ERP維護績效.xlsx」範本長得一樣的月報。整套計算與版面都在
`scripts/erp_kpi_report.py` 裡，這個 skill 的工作是：**確認格式 → 跑腳本 → 讀懂結果回報**。
不要自己另外用 pandas 重算 KPI：口徑（妥善率只扣 BD 停機、MTTF 分母含全部類別、期間分鐘數…）
是逐台設備驗證過的，重算只會產生第二套數字。

## 流程

### 1. 找到輸入檔

- 使用者附在對話裡 → 直接用附件路徑。
- 使用者指到電腦上的資料夾 → 用 device 工具把 .xlsx 抬進來（需要 pandas，在 workspace 跑）。
- 一個資料夾裡有多個 xlsx 時，優先挑工作表含 `DATA`＋`完工資料`＋`未完工資料` 的那一份；
  多份都符合就問使用者要哪一份，不要猜。

### 2. 檢查格式（先 `--check`，不要直接產表）

```bash
python3 <skill>/scripts/erp_kpi_report.py 來源.xlsx --check
```

印出 JSON：`ok`、`missing_sheets`、`missing_columns`、各表 `rows`、`period_guess`。
exit code 0 ＝ 可以跑；2 ＝ 格式不符。

- **ok: true** → 進第 3 步。額外工作表（如 `0_使用說明`）沒關係，腳本只讀三張。
- **格式不符** → 不要硬跑、不要自己改欄名猜對應。回報缺哪張表／哪些欄位，附上
  `assets/ERP維護績效_輸入範本.xlsx`（空白範本，含欄位規格頁），請使用者照範本整理。
  常見情況：欄名多了空白或全形括號（腳本會 strip 前後空白，但 `停機時間(分)` 的括號必須是半形）、
  三張表被拆成三個檔案（請使用者合併成一份，或用 pandas 合併後再跑）。
  欄位完整定義在 `references/input-spec.md`。

### 3. 產表

```bash
python3 <skill>/scripts/erp_kpi_report.py 來源.xlsx -o 輸出.xlsx [--as-of YYYY-MM-DD] [--period 起 迄]
```

- 輸出檔名慣例：`<來源檔名>_程式產表.xlsx`，放在來源檔旁邊（使用者資料夾）。
- `--as-of`：未完工單「結單日數」算到哪天。**重現舊月報時一定要指定**（例如資料是 2024 年 5 月中匯出的，
  就給 `--as-of 2024-05-24`），否則逾期判定會用今天算，數字對不上。使用者沒說就用預設（今天），並在回報裡提一句。
- `--period`：報表期間。預設自動抓完工資料「完成日」最多的那一年、1/1 到最後一個月月底；
  `period_guess` 看起來不合理（例如只有零星幾筆落在別的年份）才需要指定。
- `--repeat-month 4月`：重複性故障頁預設看期間最後一個月；使用者要固定看某月才給。

需要 `pandas`、`openpyxl`；缺的話 `pip install pandas openpyxl --break-system-packages`。

### 4. 讀結果並回報

腳本會印：報表期間、基準日、三表清理後筆數、校正紀錄筆數。回報時把這些講清楚，特別是：

- **資料校正紀錄**（輸出檔最後一張 `_資料校正紀錄`）：程式覆寫了哪些人工值。開檔讀出來，
  分類摘要給使用者（例：「DATA 移除 6,318 列重複、3 台設備妥善率與人工填寫不同、7 筆 DATA 未結案單不在未完工資料」）。
  這是「以程式為準」原則的落地——使用者需要知道哪些原始數值被改了。
- 幾個關鍵總計（完工單數、BD 單數、逾期筆數、結單率）讓使用者快速對一眼。
- 輸出檔透過 SendUserFile 交付；若來源在使用者電腦資料夾，也用 device_commit_files 寫回同一資料夾。
- 篇幅控制在半頁內：參數一行、關鍵數字一張小表、校正紀錄摘要、假設一到三點。使用者要的是檔案，
  回覆是讓他知道「程式動了什麼、哪裡要留意」，不是把每張表念一遍。

### 5. 使用者要調口徑或門檻時

所有門檻在腳本頂端的 `Config`（>10 次、≥15 小時、<30 天、<99%、1440 分、720 分、前 10 名…），
顏色／欄寬／圖表尺寸在 `SHEET_STYLE`／`TAB_COLOR`／`COL_WIDTH`／`CHART_SIZE`。
改完要重跑，並提醒使用者這份輸出跟舊月報不再可比。
KPI 公式在 `kpi_per_equipment()`，改公式前先確認使用者真的要改定義，
因為妥善率「只扣 BD 停機、Work Plan 不參與」是範本原作者的口徑，不是 bug。

## 產出內容（讓你能回答「這張表在算什麼」）

| 工作表 | 來源 | 口徑 |
| --- | --- | --- |
| 完工類別統計總表 | 完工資料 | 依維修類別（BD/IM/MR/SI/OH）的次數、工時、停機時數與佔比；右側依月份 |
| 完工故障原因分析總表 | 完工資料 | 依故障代碼 |
| 未完工統計(機)/(電) | 未完工資料 | 機械組／儀電組，年×月交叉 |
| 結單率 | DATA（去重） | 當年各月：完工數（按完成日）÷ 開立數（按需求日） |
| 逾期結單 | DATA | 需求日 ≥ 期間起日且結單日數 > 重要順序允許天數 |
| 重複性故障 | 完工資料 BD | 期間最後一個月，同設備同故障代碼 ≥ 2 次 |
| 設備故障維修次數／工時 總表＋篩選 | 完工資料 BD | 設備×月；篩選 >10 次、≥15 小時 |
| PLAN WORK 總表／篩選 | 完工資料 | 設備×類別工時；篩選 IM+MR 前 10 名（含同分） |
| 故障原因再現性 總表／篩選 | 完工資料 BD | 設備×故障代碼；篩選 ≥5 次 |
| MTTF總表／MTTF<30天 | 完工資料 BD | (期間分鐘 − Σ停機) ÷ 完工單數，換算成天 |
| 停機>24h／維修>12h | 完工資料 BD | 單筆停機 >1440 分／維修 ≥720 分明細 |
| 妥善率總表／妥善率<99% | 完工資料 | (期間分鐘 − Σ停機[僅 BD]) ÷ 期間分鐘 |
| 完工資料／未完工資料／DATA | — | 清理＋重算後的三張來源表（Excel 表格 KPI_data／未完工資料／DATA） |
| _資料校正紀錄 | — | 參數、公式、以及每一筆被程式覆寫或排除的資料與原因 |

## 已知限制

- 輸出是靜態數值，不是樞紐分析表：外觀一樣，但不能在 Excel 裡拖欄位。使用者若要可互動的樞紐，
  說明這點並問是否需要另一條「保留原檔樞紐、只抽換資料」的路線。
- 故障代碼、維修類別、停機／維修分鐘是人工加註欄位，程式無法補；空白會以「(空白)」進入報表並記在校正紀錄。
- 未完工資料若漏列了 DATA 裡未結案的單，程式只提示不自動補（回溯多久以前算未結案沒有明確規則）。

## 範例對話

**使用者**：「這是五月的派工單匯出，幫我產維護績效報表」（附 xlsx）
**做法**：`--check` → ok → 跑腳本（沒給基準日就用今天並提一句）→ 讀校正紀錄 → 交付檔案＋摘要。

**使用者**：「幫我重跑 2024 年 1～4 月那份，我要跟原本的月報比」
**做法**：問或推斷原月報的匯出日期當 `--as-of`（沒有就用期間結束後最近的合理日期並說明）→ 跑 → 把預期差異講清楚（去重、MTTF 填在非 BD 列等）。

**使用者**：「檔案裡只有 DATA 這張表」
**做法**：`--check` 會列出缺 `完工資料`、`未完工資料` → 附空白範本，說明這兩張要從 DATA 篩出並人工加註後才能算 KPI。
