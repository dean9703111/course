# ⚖️ 課前必讀：主管機關的 AI 使用指引

> **在醫院用 AI，要思考的不只是 AI 有多強，而是可以在什麼場景用**
> 衛福部已於 115 年 5 月 29 日函頒《醫療機構應用生成式人工智慧指引》（衛部醫字第 1151663164 號）。
> 今天課程中的每一個操作，都請放在這份指引的框架下思考——`它就是醫療場域使用 AI 的遊戲規則`。

## 指引懶人包

### 📜 指引在講什麼

[flow]
- **適用對象** — 預備導入或已導入生成式 AI 的`公私立醫院及診所`；情境涵蓋`病歷撰寫輔助、臨床決策支援、行政文書撰擬、病人溝通工具`
- **指引性質** — 屬`行政指導`而非強制規定，但機構仍應依實際情況與`個人資料保護法、醫療法`等法令採取適當管理措施
- **管理框架** — 依導入流程分為`導入前評估 → 導入與整合 → 導入後使用與監管`三階段、九項注意事項
[/flow]

### ⚠️ 指引點名的六大風險

[flow]
- **輸出結果風險** — AI 可能產出`看似合理但實際不正確`的內容（幻覺），如編造不存在的文獻
- **使用者依賴風險** — 過度信任 AI、把產出當最終結論，`判斷能力反而退化`
- **資安攻擊風險** — 提示詞注入（prompt injection）、資料中毒與`資料外洩`等資安威脅
- **資料來源風險** — 取用`過期、不正確或不完整`的外部資料，直接影響產出品質
- **基礎模型風險** — 模型建置時`內嵌的系統性偏差`，影響判斷的正確性與公平性
- **服務中斷風險** — 依賴外部服務商，可能遇到`服務停止、模型下架`或版本更新
[/flow]

> **為什麼今天的課會一直提醒你「驗證、留白、把關」？**
> 因為六大風險中`最貼近日常使用`的，就是前兩項：AI 可能`編造看似合理的內容`（ex: 不存在的文獻、錯誤的藥物交互作用資訊），而人一旦`過度信任`，把 AI 產出當最終結論，臨床判斷能力反而會退化（deskilling）。
> 今天所有案例養成的操作習慣，都是在提醒大家這兩件事。

### ✅ 上完課後，請守住這四條底線

[flow]
1. **人負最終責任** — AI 是`輔助工具`，臨床醫師、行政主管等決策人員`負最終判斷責任`；醫事人員製作病歷文書，仍應`確實審核與簽章`
2. **病人個資不外流** — 病歷、影像、語音都是敏感資料；未經機構評估核准，`不要把可識別病人資料`貼給外部 AI 服務，練習一律`先去識別化`
3. **個人測試 ≠ 機構導入** — 個人研究、教育示範可`參照指引原則`辦理；一旦涉及`真實病人資料或臨床作業流程`，就屬導入階段，應依指引與院內程序執行
4. **臨床用途另有規矩** — 今天的案例都屬`行政作業輔助`（報表、排班、文書）；若用途涉及`診斷、治療`，可能屬`醫療器材`範疇，必要時應向食藥署申請屬性判斷
[/flow]

[/warning]

# 關鍵心法：AI 浪潮下的減壓工作哲學

## AI 除了聊天還可以製作工具

### 💬 回想一下，你平常都拿 AI 來做什麼？

[flow]
- 寫文件 - 寫信、寫報告、潤稿、翻譯、改語氣
- 查資料 - 搜尋資訊、查不懂的名詞、找靈感
- 問答 - 丟一個問題問它的意見、整理一大段文字幫我摘要重點
[/flow]

> **這些任務有一個共通點**
> 你`問一句`、AI `答一段`，最後會拿到一段可以複製貼上的`文字`。
> 但下次再遇到同樣的事，你還是得`從頭再問一次`。

### 🛠️ 現在 AI 不只會「回答」，還能「幫你做事」

> **掌握進階的 AI 技巧**
> 現在它能`接上日常工具`讀寫資料、把`重複的流程`設計為技能，甚至幫你`做出一個工具`。
> 這些技巧，才是`導入 AI 自動化工作流`的關鍵。

[flow]
- 允許讀寫雲端檔案 - 用 `Connector` 讓 AI 接上你的工具，自己去讀 Gmail、Google Calendar、Notion
- 設計自己的第二大腦 - 分類建立 `Project`，將原本需要大腦記憶的「專案資訊、會議紀錄、公司規範、行動指南」放進去
- 建立可重用的方法 - 把 SOP 設計成 `Skill`，一句話就能重複執行，讓 AI 從通才變專才
- 整理檔案、做出產品 - 透過 `Cowork` 幫助整理電腦上的檔案，根據需求建立能輸出穩定結果的程式
[/flow]

## Project：建立專屬知識庫

### 😩 痛點：背景每次重講，品質還不穩定

[flow]
- **同個聊天視窗中** - AI 對話有上下文限制，`超過會變笨`；討論不同主題，`幻覺會嚴重`
- **開新的聊天視窗** - 你需要`重新交代背景資訊`，每次打的指令都不一樣
- **需要重新上傳參考資訊** - 如果檔案放在電腦，而你剛好`人在外面就無法操作`。
[/flow]

> **AI 有記憶能力，但不是無限的**
> 儘管現在 AI 已經具備記憶能力，回答時會參考你過去與他的對話，但`非常隨機`。
> 而 Project 的設計，就是讓`隨機變成穩定`。

### 🧠 根據不同情境建立對應專案

[flow]
- **不同專案扮演的角色不同** - 組員、主管、甲方、乙方
- **手上有多個專案進行** - 每個專案背後的知識庫都不一樣
[/flow]

> **專案（Project）就像第二大腦**
> 現在的工作通常都是`多工進行`，但人類切換到另一個專案時大腦會混亂。
> 既然如此，就讓 AI 幫你記住`專案的細節、自己扮演的角色`

### 🗂️ Project 基礎架構

[flow]
- **指令（Instructions）** — 我是誰、這個專案在做什麼、固定規則（ex: 要參考的資源、不要做的事）
- **知識庫（Files）** — 參考資料，可以是品牌指南、專案規格、文案範本、決策紀錄
- **記憶（Memory）** — 這個 Project 使用一段時間後，就會更理解你想要做的事
[/flow]

[/warning]

```prompt [label="instructions：專案記憶助理"]
1. 回答一律以知識庫內的規格／會議／決策為準，並標明出處（哪份文件、哪次會議、哪筆決策編號）。

4. 決策日誌中標示「已被取代」的條目，回答時以取代後的最新決策為準，但要補一句「原本是…，後來因…改為…」，讓我看得到演變。

```

### 🤯 流程都在某個人腦袋裡

[flow]
- **關鍵人物不在，流程就卡死** - 「這份文案怎麼寫？系統怎麼設計的？專案下一步該做什麼？」如果答案全在某個`資深同事`的腦袋；他一請假、離職，這一切就需要`重新摸索`。
- **交接靠口耳相傳，品質全憑運氣** - 新人上工時，只拿到`零散筆記`和`口頭經驗`；因此報告、信件、文案...每個人的`格式、品質`都不一樣。
- **需要手把手教學，難以擴散** - 許多流程需要`實際 Demo`才能搞懂，因此就算有好方案也`擴散不出去`，案例難以複製到不同部門。
[/flow]

### 📋 提示詞一直複製貼上

[flow]
- **存了一堆 Prompt，要用時翻半天** - 提示詞散落在`記事本、Notion、聊天記錄`；真的需要使用時，光是找出`最後一版`就浪費一堆時間。
- **換個情境就得調整提示詞參數** - 同一套文案 Prompt，換個品項、從 IG 改到 EDM 就得`手動微調`，浪費時間。
- **規則改了，舊版本卻沒跟著改** - 新增一個`禁用詞`、調整了`品牌語氣`，但同樣的 Prompt 已經`被複製到十個 Projects`；漏改一處，錯的版本就`默默繼續產出`。
[/flow]

### 📝 彙整對話生成 Skill

> **不要急著關閉對話窗**
> 使用 AI 一段時間後，你會發現`好的結果需要經過多輪對話`才能得到。
> 而你`引導 AI 的過程`，其實可以把它設計成 Skill，或是拿來優化既有的 Skill。

一年前，建立提案企劃草稿需要與 AI 討論`半小時以上`，並`來回執行這麼多的 Prompt`

#### STEP 1: 產生合適的 Prompt（聚焦需求）

```prompt [label="先簡單說明背景"]
我準備製作一個[給台灣新創行銷公司導入 Claude AI]的提案企劃

```

#### STEP 2: 詢問是否有需要補充的內容

```prompt [label="看似完善的 Prompt 可能還有可以優化的地方"]

```

![如果 AI 有自己跳出選項，STEP 3 可以跳過](./assets/claude-skill-plan-check.png)

#### STEP 3: 讓 AI 幫我們補齊不足的資訊（也可以自行回答）




#### STEP 6: 用紅藍隊的概念攻防（競爭者）

```prompt [label="從挑戰者的角度來優化企劃"]
你是這份提案企劃的[競爭者]，盡可能列出這份企劃的不足之處。
並說明自己可以做到哪些更完善、可行的方案。
```

#### STEP 7: 生成完善企劃

```prompt [label="最後要生成完善的企劃"]
請扮演[提案企劃]的專家，在了解[不足之處、更完善的方案後]後，以最專業的角度，重新完善這份企劃。
```

## Vibe Coding 是什麼？

> **透過白話文跟 AI 對話，逐步完善工具的流程**
> - **優點**：可以快速完成初版
> - **缺點**：結果較不可控、未來較難維護
> 若沒有程式背景，`把想做的事、期待的結果講清楚`是最重要的事

### 🧩 認識常見名詞

- **AI Agent**：不只是問一句答一句的聊天機器人，而是能`理解任務、操作你的檔案、自己串好步驟、把事情從頭做完的助手`
- **Token**：AI 的`計費與容量單位`，可以想成 AI 的「貨幣」，不同付費方案的額度不同
- **Model**：AI 的「大腦」，不同模型的`智商不同`，消耗的 Token 也不同；`越聰明的模型，花的 Token 越多`

> **工程師的角色，也在改變**
> 當「把功能寫出來」越來越容易，工程師真正的價值，就從「會不會寫程式」移到`懂不懂這個產業、能判斷出最適合的方案、知道為什麼要這樣做`。
> 大家在產業累積的 know-how，就屬於這類`最難被取代的價值`。

# 報表自動化：只要規則明確，AI 就能自動化

> **從零開始示範，是為了讓大家知道會遇到哪些問題**
> 比起最後的成果，中間`協作、驗證、修復`的過程更重要。

## 吃掉工作時間的月報

### 😮‍💨 來源數據很多

- 於 TCPI／QIP 系統提報後，下載一(1)~(5) 來源報表
- 更新月報數值：本院分子／分母／數值要用 VLOOKUP 比對來源報表
- 燈號用 IF 公式判斷、SPC 圖要人工看是否 >2σ／>3σ、再依燈號整列填色
- 最後把紅燈／黃燈指標，依構面分類複製到 WORD 摘要表
- **一份約 40–60 分鐘，最卡在 SPC 逐筆確認與 WORD 表格分類貼上**

![對我來說，這些資訊是完全陌生的](./assets/monthly-example.png)

### 🔍 痛點拆解：時間到底卡在哪

[flow]
- 抄與比對 — 分子／分母／數值一格格 VLOOKUP 比對來源報表，`一格錯，整份數據就錯`
- 判燈號 — IF 公式判紅黃綠，SPC 圖還得`人工盯 >2σ／>3σ`，一張張看眼睛很快就花
- 分類貼上 — 紅黃燈指標`依構面手動剪貼`進 WORD 摘要表，格式還不能跑掉
[/flow]

> **這件事「不難，卻很煩」**
> 每一步都是`機械式`的抄、比、貼，不需要判斷力，卻`最吃時間、也最容易出錯`。
> 這正是 AI 最該接手的部分——把你從`重複勞動`裡放出來，只留下`最後把關`那一下。

4. 要求自測 — 請 AI 撰寫測試程式，`提高成功率`，也讓未來加功能時更穩定
5. 親手驗收 — 實際打開網頁、下載 Excel／Word，`人工驗證馬上抓到 AI 自己沒發現的問題`
6. 換法修復 — 修不好就換個問法：`給角色（專業工程師）、給證據（錯誤檔案）、換更聰明的 Model`
[/flow]

### 💡 Vibe Coding 重要心法

- **驗收要在真實環境**：AI 的「驗證通過」是用它自己的工具量的，`成品一定要用真實環境親手打開`
- **修 Bug 靠方法，不靠運氣**：描述不出技術細節沒關係，`換個問法、附上證據、調高 Model 與 Effort、或是開一個新對話`
- **專業是最後一哩路**：你對資料的熟悉度，正是把工具`從 80 分推到 100 分的關鍵`

> **你不需要會寫程式，但一定要驗收**
> 整個過程我們`沒有寫一行程式`；但結果需要`親自驗收`，並在遇到問題時`引導 AI`。

[warning title="若打算正式導入請從多角度進行驗證"]
依衛福部指引，AI 在醫療場域是`輔助工具`，`行政主管與經辦人負最終判斷責任`，AI 產出的月報`必須經人工覆核`才能上呈。
另外，自己做的工具若要`全院正式導入`，記得依指引經`主責單位`完成風險盤點與評估，而不是個人默默上線。
[/warning]

# 護理師排班：從排一整天變成「AI 排、你校準」

> **這個情境比月報表難很多**
> 它是一個`有很多規則要同時滿足`的問題。
> 示範的重點`不是一鍵排出完美班表`，而是「怎麼跟 AI 討論、技術框架調整評估、實戰應用的優化。」

## 排班為什麼這麼難

### 😩 排班者的日常：規則複雜又容易衝突

[flow]
- **一次要顧十幾條規則** - 最低人力、連續天數、11 小時休息、包班……漏一條就得整段重排
- **牽一髮動全身** - 改一個人的班，`連鎖影響`前後好幾天、好幾個人
- **對錯藏在細節** - 違規的那一格`肉眼很難一眼抓出`，靠人工檢查又慢又累
- **每個月都要重來** - 這不是做一次就好，是`月月循環`的固定折磨
[/flow]

### 🧷 排班的基礎規則

1. **每班最低人力需求**：D:16／E:16／N:14
2. **連續上班天數**：D 最多 5 天／E 最多 5 天／N 最多 4 天
3. **排班階層分為 5 階**（資深 A～資淺 E）：每階層每天上班人數上限`如 Excel 表內公式`
4. **不能 N off D**：不能`大夜後又接白班`
5. **包班與班別限制**：包班（同班別 >15，`綠底、藍底`人員，每月會變動）以`純班（一種班別）`為原則；未包班人員每月`至多 2 種班別`；更換班別時，至少應有`連續 11 小時`的休息時間
6. **小組長人力**：每日 D、E、N 小組長都要 `≥ 2`
7. **新人不排班**
8. **標示黃色＝預排假**：不排班
9. **例假與休息日**：2 週內至少 `2 日例假`；4 週內至少 `8 日例假及休息日`（休息日可補休、特休）；六、日休假總次數盡量`各人員平均`
10. **工時上限**：每日正常工時 `≤ 10 小時`、4 週總正常工時 `≤ 160 小時`

> **這讓我回想起當兵時的哨表**
> 日哨夜哨的哨點不同、資深資淺能站的崗位不同、每班哨最短間隔時間、如何安排休假讓重要哨點都有人，在人力不足時的狀態下如何盡可能公平。

#### 第 1 次試用

> Vibe Coding 製作工具的重點`不在於會不會寫程式`，而是你是否具備`知道哪裡不對`的判斷了；而正是 AI 和外部工程師`最缺`的東西。

## 純前端減少資安疑慮

### 🧩 前端、後端、資料庫，各自負責什麼

- **前端** — 你在瀏覽器裡`看得到、點得到`的畫面，負責`呈現資訊、接收你的操作`
- **後端** — 跑在`伺服器上`的程式邏輯，負責接收前端送來的請求、`運算處理後回傳結果`
- **資料庫** — 負責`長期保存資料`，後端把要留存的資料寫進去、需要時再查出來

### 🔒 純前端＝資料不出你的電腦

今天兩個工具（月報表、排班）都是`純前端網頁`，`沒有後端伺服器、也沒有資料庫`。

- 所有運算都在`你自己的瀏覽器`裡跑，`資料完全不離開電腦`、不上傳任何伺服器
- 所以`沒有資安疑慮`，可以放心在醫院電腦、甚至離線環境使用
- 這也是我要求 AI 設計時要`「雙擊 html 就能用」`的原因

> **但想讓系統更完善，就是另一個世界了**
> 如果你想`把資料儲存起來`不用每次重新上傳、讓不同的人有`不同權限`（有人只能`瀏覽`班表、有人可以`編輯`），甚至涵蓋`請假`等流程，就進入`後端＋資料庫`的範疇。
> 系統會開始`碰到個人隱私資訊`，`帳號權限、資安防護`每一項都要顧。
> 這時就`真的需要專業工程師`把關，**做雛形依然可以用 Vibe Coding，但隱私請交給專業**，這條界線要分清楚。

## 案例回顧

### 🧭 我們到底做了什麼

[flow]
1. 先讀懂 — 讓 AI 讀懂 Word 規則＋`藏在 Excel 公式裡的規則`，列出規則、反問確認後才動工
2. 問方案 — 先問「有推薦的組合嗎」，立下`格式一致、公式保留`兩條底線；想換架構（Python → 雙擊 html）也`先用問句確認可行`
3. 小步做 — 先完成 MVP，並要求 AI `自我驗證通過`：幾千個格子，不可能人工逐格驗
4. 反例糾錯 — 不說「怪怪的」，`用具體反例`（端午節不是每月都有、7 天後接 10）逼出設計層的錯
5. 迭代到直覺 — 用自己的排班工作流提需求：對照上月、違規標色、手動預假，`做好的功能也能推翻重做`
6. 給真實使用者試 — 護理長試排抓出`跨月盲點與包班等規則問題`，讓我們看到優化是沒有盡頭的路
[/flow]

### 💡 經驗是非常重要的

- **AI 排、你校準**：執行與測試都交給 AI，`你只負責判斷與決策`
- **現場的 know-how 只有你有**：包班、例假、兩種班上限……我一開始`一個都不懂`，全是`護理長回饋後`我才注意到的；工程師對這些陌生，就像你對技術陌生，但`技術可以問 AI，現場的 know-how 沒得問`

> **這就是 Vibe Coding 真正的魅力**
> 把做工具的主導權，`交回到最懂需求的人手上`。

# 加入 Git 版控：否則某次 AI 改壞就沒有回頭路了

## 為什麼要加入版本控制

### 🗂️ 給成品一個「家」，還附贈後悔藥

- 成品需要一個「家」，才不會`散落在桌面各處`，換電腦、重灌就找不回來
- GitHub 提供**版本控制**：`每次上傳都是一個「還原點」`，哪天 AI 改壞了，隨時可以`退回上一版`，這正好治「不知道被改壞」的痛
- 放上 GitHub 之後，還能透過 **GitHub Pages** 把工具`變成一個網址`，傳給同事就能直接用

> **不用打指令，也能用 GitHub**
> 很多人以為 GitHub 是工程師專用，其實今天要做的事`全程用滑鼠點一點、檔案拖一拖`就能完成——因為前面我們已經請 AI 把程式都收在 `code` 資料夾裡了。

- 就算改壞了也不怕，`每一版都在 GitHub 留著`，隨時退得回去


# 🧰 附錄：想更進一步，先把環境準備好

> **Cowork 可以幫你完成雛形，但打磨細節需要 Claude Code**

## 為什麼要安裝工具？

### 🧠 AI 是大腦，這些工具是它的雙手

- 今天製作的範例（月報表、排班），Cowork `內建環境`就能跑，你什麼都不用裝
- 但像`音檔轉字幕`要用到 Python、`生成講義／提案`要用到 Node.js —— 這些就是 AI 動手的「雙手」
- 沒有這些工具，AI 就算知道怎麼做，也是`有腦無手`

## 建議安裝的工具清單

### 📋 一張表看懂：裝什麼、為什麼

| 工具 | 一句話說它是什麼 | 為什麼要裝 | 哪裡拿 |
| --- | --- | --- | --- |
| **Git** | 專案的「時光機」 | 改壞了能退回上一個版本 | [git-scm.com](https://git-scm.com/) |
| **GitHub 帳號** | 雲端「保險箱」 | 成品存上雲、跨裝置同步 | [github.com](https://github.com) |
| **nvm ＋ Node.js** | 網頁工具 | 實用的套件、網頁框架 | [nvm](https://github.com/nvm-sh/nvm) |
| **Python** | 工具箱 | Agent Skill 腳本常用 | [python.org](https://www.python.org/downloads/) |
| **IDE（程式碼編輯器）** | AI 的「工作桌」 | Cursor／VSCode 擇一即可 | [VSCode](https://code.visualstudio.com/) |
| **Claude 帳號（Pro 以上）** | 一張「門票」 | Cowork、Claude Code 都要它 | [claude.ai](https://claude.ai/) |

## 怎麼裝：Mac 與 Windows 分開看

> **看到「終端機」不用怕**
> 它就是`用打字下指令`的視窗：`Mac` 用「終端機（Terminal）」、`Windows` 用「PowerShell」。下面只列最關鍵的指令，其餘交給 AI 補完。

### 🔧 Git ＆ GitHub 帳號

先確認裝了沒、身份設了沒：

```terminal [label="確認 Git 版本與帳號設定"]
git --version
git config --global user.name
git config --global user.email
```

> **若名字或 Email 是空的，請補上**
> git config --global user.name "你的名字"
> git config --global user.email "你的 Email"

### ⚙️ nvm ＆ Node.js

我們`不直接裝 Node.js`，而是先裝 `nvm`（Node 的版本管理員），之後要升級、切換版本都方便。

#### Mac / Linux

```terminal [label="安裝 nvm"]
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.4/install.sh | bash
```

#### Windows

到 [nvm-windows releases](https://github.com/coreybutler/nvm-windows/releases) 下載 `nvm-setup.exe` 安裝。

裝完 nvm，`重開終端機`，再裝 Node.js：

```terminal [label="安裝並確認 Node.js"]
nvm install --lts
nvm use --lts
node -v
```

### 🐍 Python

#### Mac / Linux

```terminal [label="確認 Python 版本"]
python3 --version
pip3 --version
```

#### Windows

```terminal [label="確認 Python 版本"]
python --version
pip --version
```

> **電腦有多個 Python 版本，套件裝了卻找不到？**
> 交給 AI 就好：「請幫我檢查目前 python 與 pip 指向哪個版本，並設定 alias 讓 python、python3、pip、pip3 都指向同一個版本，避免`套件版本飄移`」。

### 🤖 Claude Code

Cowork 免安裝就能用；`Claude Code` 是它更萬能的兄弟，但要在終端機操作。

#### Mac / Linux / WSL

```terminal [label="安裝 Claude Code"]
curl -fsSL https://claude.ai/install.sh | bash
```

#### Windows PowerShell

```terminal [label="安裝 Claude Code"]
irm https://claude.ai/install.ps1 | iex
```

![這是 Claude Code 安裝成功的參考畫面](./assets/claude-install.png)

裝完輸入 `claude` 啟動，第一次會請你`登入 Claude 帳號`。

[warning title="Claude Code 更萬能，也更危險"]
- 它能直接新增、修改、刪除你電腦上的檔案，能力比 Cowork 大得多
- 沒有程式背景時，AI 問「要不要執行」，多數人會直覺按「接受」—— 只要錯一次就可能出事
- 剛開始寧可慢：權限選「每步先問」，看清楚再放行
- 醫療電腦若有安裝限制，`先問過資訊室`再動手
[/warning]

## 確認有安裝成功：一行指令確認全部就緒

### ✅ 一次檢核所有版本

#### Mac / Linux

```terminal [label="一次檢核所有版本"]
git --version && node -v && python --version && claude --version
```

#### Windows PowerShell

```terminal [label="一次檢核所有版本"]
git --version; node -v; python --version; claude --version
```

![四個版本號都跳出來就代表環境就緒，你的版本可能跟我不同，有跳出來就對了](./assets/tool-check.png)

### 🛟 卡關速查表

| 狀況 | 處理方式 |
| --- | --- |
| 出現 `command not found` | 該工具還沒裝，回上面對應段落補裝 |
| Node 版本偏低 | `nvm install --lts && nvm use --lts` |
| Git 沒設定身份 | 補上 `git config --global user.name / user.email` |
| Claude Code 打不開 | 執行 `claude`，依畫面完成登入 |

[warning title="裝不起來很正常，不是你的問題"]

- 每台電腦狀況都不同，出錯是常態，不用自我懷疑
- 最好的除錯夥伴就是 AI：把錯誤訊息`原封不動`複製或截圖丟給它，請它一步步帶你解
[/warning]
