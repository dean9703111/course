# 教師與學校行政 AI 實戰課

對象為學校老師與學校行政，預設會使用瀏覽器與辦公軟體，沒有程式開發背景。每堂以 **100 分鐘教學與操作** 設計，休息與 Q&A 另計；每份講義約 400 行，實際節奏以任務完成與驗收為準。

主要內容改編自安美諾、EDA、三總等既有 `course/` 講義與 `video/manus/` 系列文稿。校園情境、練習題與示範資料是教學改編，不代表曾替特定學校執行的成果。

## 兩組工作流，各自能帶走成果

**第一組：ChatGPT → Codex。** 從一份閱讀活動通知開始，學會把素材變成適合不同對象的文字、讓家長與承辦人視角挑錯，再存成可重複使用的方法。接著把同一組需求交給 Codex，生成可開啟的摘要、表格、自選主成果與教材圖片，另可選做視覺化看板。Google 應用與排程用講師測試帳號示範，學員在權限允許時再操作。

**第二組：Claude → Cowork。** 重新從工具、資料與 SOP 的分工切入，以這一組自己的虛構素材建立課務助理，再產出活動工作包與班級分組器。這兩堂會重講必要觀念，不要求學員記住前兩堂的術語與操作。

兩組都練習「先釐清 → 跑一次 → 人工驗收 → 保存好方法 → 換情境再測」。重複的是能遷移的工作習慣；不同工具的入口、授權與排程條件，分別依官方文件說明。

## 100 分鐘的取捨

- **主線實作**：每堂完成一條連貫工作流，讓學員有自己的產出；教師與行政可選與工作最接近的分支，不要求每個人兩條全做。
- **講師示範**：需要外部授權、等待生成或特定帳號功能的步驟，使用預先確認的測試帳號示範；學員先觀察資料來源與結果如何驗收。
- **課後延伸**：額外變體與完整版本控制操作留在講義，方便回去加做；若現場進度較慢，先確保主線成果完成。
- 各堂 `content.md` 開頭的講師備註列出分段分鐘，合計 100；不把末尾 Q&A 或休息算進去。
- 練習素材提供下載入口，先下載解壓縮再操作。Google 連接示範需由講師將虛構郵件、文件、行事曆資料放入測試帳號，下載包不會自動建立雲端內容或授權。

收穫的判準：能否說出自己省掉哪個步驟、成品如何驗收，以及換成下週的工作時要改哪幾個條件。示範看懂與學員親手完成，備課時分別記錄。

## 去識別化案例的使用方式

沿用既有影片的「上傳前先檢查」「多工作表容易漏遮」「PDF 白框不等於移除文字」「編碼表與文件分開保存」觀念，改成學校情境。練習只使用虛構資料，不把真實學生紀錄交給雲端 AI 再請它去識別化。

改姓名、刪姓名、加代碼都不能自動保證無法辨識。班級、特殊事件、日期或少數身分組合，仍可能讓熟悉情況的人辨認出對象。是否能使用資料，仍須依學校核准的工具、資料範圍與作業流程判斷；講義不假設任何特定學校已核准。

也要區分「AI 在開發時讀到什麼」與「完成的小工具在執行時傳出什麼」。檔案在本機、使用桌面 App、工具是純前端，都不能單獨證明資料不會傳到雲端。

## 上課前確認

- 以授課帳號確認各工具功能、授權範圍與校方帳號限制；沒有連接器權限時，使用講義提供的檔案練習方式。
- 操作畫面可能隨版本調整；講義以工作目標與驗收為主，圖片需配合現場版本補拍。
- 每堂教學操作時間已確定為約 100 分鐘；授課日期為 11/23、11/24、11/26、11/27；每日起訖時間、學員任教學段與實際核准政策尚未指定，因此沒有代填。
- `content.md` 是內容來源；修改後需重新產生 `index.html` 與 `assets/og-image.jpg`。

從本儲存庫根目錄執行（每堂各跑一次）：

```bash
node .agents/skills/course-page-generator/scripts/build.mjs course/tschool/chatgpt --check
node .agents/skills/course-page-generator/scripts/generate-og.mjs course/tschool/chatgpt
```
