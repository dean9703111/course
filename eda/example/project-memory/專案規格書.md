## 1. 背景與問題陳述
現有會員系統只有「消費集點換贈品」，存在三個問題：
1. **集點誘因薄弱**：點數兌換率低（< 8%），對回購幾乎沒有拉動。
2. **體驗一視同仁**：高消費會員與一次性客人看到一樣的首頁，缺乏分級尊榮感。
3. **推薦無個人化**：首頁熱銷榜人人相同，與個人喜好脫節，點擊轉換差。

行銷與數據團隊的假設：把「集點」升級為「分級會員 + 個人化推薦」，能同時提升回購率與客單價。

## 2. 專案目標與成功指標
| 類型 | 指標 | 現況 | 目標 | 量測方式 |
|---|---|---|---|---|

| 次要 | App 月活躍（MAU）| 基準 | +15% | App 後台 |

| 護欄（不可惡化）| 客服進線量 | 基準 | 不顯著上升 | 客服系統 |

## 3. 名詞定義（Glossary）
- **回購率**：首購後 90 天內再次下單的會員比例。
- **近 12 個月消費**：以「出貨完成日」計，退貨金額需扣除。
- **冷啟動**：新會員無購買紀錄、無法個人化推薦的狀態。
- **可解釋推薦**：推薦項目需顯示理由（例：「因為你買過 X」）。
- **保級進度**：距離維持或升級所需的剩餘消費金額。

## 4. 範圍（In Scope）
1. **會員分級制度**：一般／銀卡／金卡，依年消費金額自動升降級。
2. **個人化首頁**：依購買紀錄推薦商品，含冷啟動 fallback。
3. **推播通知中心**：可分類開關，含頻率上限。
4. **第三方登入**：第一期 Apple、Google；LINE 於第二期（v1.3）補回。
5. **會員權益頁**：顯示目前等級、保級進度、專屬優惠。

## 6. 使用者輪廓（Persona）與使用者故事
**Persona A：高黏著金卡客「美玲」**
- 每月固定回購，重視尊榮感與專屬優惠。
- 使用者故事：「身為金卡會員，我想在首頁一眼看到我的專屬優惠，這樣我會更常打開 App。」

**Persona B：價格敏感一般客「阿凱」**
- 有活動才買，對推播敏感（太多會關通知）。
- 使用者故事：「身為一般會員，我想自己決定收到哪類推播，這樣我不會因為被洗版而封鎖通知。」

**Persona C：剛註冊新客「小婷」**
- 無購買紀錄，首頁不能開天窗。
- 使用者故事：「身為新會員，我想看到有用的精選推薦，而不是一片空白或亂推。」

## 7. 功能需求（含驗收標準）
### 7.1 會員分級
- 等級：一般 / 銀卡 / 金卡。
- 升級門檻：近 12 個月消費 銀卡滿 NT$10,000、金卡滿 NT$30,000（D-009 採「金額」而非「次數」）。
- 重算：每月 1 號凌晨重算；**降級給予一個月緩衝期**，UI 顯示「目前等級保留至 X 月」。
- 升級即時生效；降級於緩衝期結束後生效。
- 邊界案例：跨月剛好達標、退貨導致掉出門檻、CRM 資料 T+1 延遲未到齊（延後重算並告警）。
- **驗收**：模擬會員跨門檻消費，次月 1 號等級正確；降級會員在緩衝期內仍享原等級權益。

### 7.2 個人化推薦
- 第一版（v1.1）採 **規則式**：同類別熱銷 ×1.0 + 個人回購品項 ×1.5 + 新品 ×0.8 加權，**不導入 ML**（D-001）。
- 推薦需 **可解釋**：顯示「因為你買過 X」（D-012）。
- **冷啟動**：無紀錄者顯示行銷維護的「本月精選」清單，最多 12 項（D-003）。
- 第二版（v1.3）導入 **ML 推薦**，與規則式 **並行 A/B**，規則式保留為對照組與 fallback（D-006、D-015）。
- 邊界案例：推薦不足 N 項時用熱銷補滿；理由文字缺失時不顯示空白（回退「為你精選」）。
- **驗收**：有購買紀錄者推薦含至少 1 項回購相關品；冷啟動者顯示本月精選；每則推薦都有理由文字。

### 7.3 推播通知中心
- 分四類：訂單、優惠、會員權益、系統公告，使用者可各自開關。
- 預設值：訂單／系統公告預設開；**優惠（行銷）類預設關**，由會員主動開啟（D-014）。
- **頻率上限**：行銷類每位會員每週最多 3 則（D-013）。
- **等級異動預告**：即將降級者提前 7 天推播（D-005，v1.2.2 新增）。
- **驗收**：關閉某類後不再收到該類；行銷類超過上限不再發送；降級前 7 天收到預告。

### 7.4 第三方登入
- 第一期：Apple、Google（D-002 移除 LINE）。
- 第二期：補回 LINE（D-007）。
- 採 OAuth、不落地密碼；可綁定既有會員（以 Email 比對，衝突時走客服驗證）。
- **驗收**：可用 Apple / Google 完成註冊與登入，並綁定既有會員。

### 7.5 會員權益頁
- 顯示：目前等級、保級進度條、距升級剩餘金額、專屬優惠列表。
- **驗收**：金額與等級與後台一致；保級進度計算正確。

## 8. 非功能需求
- **效能**：首頁含推薦需在 1.5 秒內完成載入（P95）；推薦 API 逾時 800ms 走 fallback。
- **安全 / 個資**：推薦模型不得使用身分證、金流卡號等敏感欄位（D-014、資安檢視）；登入採 OAuth。
- **可用性**：核心流程支援深色模式與字級放大。
- **相容性**：iOS 15＋、Android 10＋。
- **可觀測性**：關鍵流程需埋點與告警（見第 17 節）。

## 9. 商業規則與資料定義
- 等級計算只認「已出貨完成」訂單；退貨金額即時扣回累計。
- 推薦加權：回購品項 ×1.5、同類別熱銷 ×1.0、新品 ×0.8。
- 「本月精選」由行銷每月 25 日前提供下月清單，最多 12 項。
- 保級進度 =（升級門檻 − 近 12 個月消費），最小為 0。

## 16. 事件埋點規格（Analytics Events）
| 事件名 | 觸發時機 | 關鍵屬性 |
|---|---|---|
| home_view | 首頁載入完成 | tier、is_cold_start |
| reco_impression | 推薦曝光 | item_id、position、source、reason_text |
| reco_click | 推薦點擊 | item_id、position、source |
| tier_changed | 等級異動 | from_tier、to_tier、reason（upgrade/downgrade）|
| push_opt_change | 推播開關變更 | type、enabled |
| push_opened | 推播被開啟 | type、campaign_id |
- CTR = reco_click / reco_impression，需可依 source（rule/ml）拆分（支援 A/B）。

## 17. 畫面與狀態（空狀態 / 錯誤狀態）
- **首頁（一般）**：上方權益卡 → 中段個人化推薦 → 下方本月精選。
- **首頁（冷啟動）**：個人化區塊以「本月精選」填補，文案「為你精選」。
- **推薦理由缺失**：不顯示空白行，回退顯示「為你精選」。
- **推薦 API 逾時（>800ms）**：顯示熱銷榜 fallback，並記錄告警。
- **權益頁載入失敗**：顯示重試按鈕，不可顯示等級為「空白」。
- **降級緩衝中**：等級徽章旁顯示「保留至 X 月」小字。

## 18. 無障礙與在地化
- 支援字級放大至 200% 不破版；色彩對比符合 WCAG AA。
- 文案集中於語言檔，預留英文版位（本期只出繁中）。
- 金額一律「NT$」格式、日期「YYYY-MM-DD」。

## 19. 發布與回滾計畫
- 採分批灰度：先 10% 會員 → 50% → 100%，每階段觀察崩潰率與客服進線 24 小時。
- 推薦模組以 feature flag 控制，可一鍵切回「純熱銷榜」。
- 回滾條件：崩潰率 > 0.8% 或出現資料錯誤等級 bug。
